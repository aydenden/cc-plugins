LLM Wiki 볼트에서 "$ARGUMENTS"와 관련된 지식을 찾아 현재 작업 컨텍스트에 주입해줘.

## 볼트 경로

```bash
WIKI="${WIKI_PATH:-$OBSIDIAN_VAULT_PATH}"
```

`WIKI`가 미설정이면 사용자에게 안내하고 중단.

## 1단계: Grep 전수검색 (1차 경로)

검색 엔진은 **CC 내장 Grep**이다. 볼트 마크다운 총량 8.5MB, 전수검색 실측 0.02초 — 인덱스도 사전 준비도 없다.

대상은 `$WIKI`의 `entities/` `concepts/` `comparisons/` `queries/`. `raw/`는 원문 더미라 기본 제외하고, 위키 계층에서 아무것도 안 나올 때만 마지막으로 훑는다.

```
Grep(pattern: "<확장된 정규식>", path: "$WIKI", glob: "{entities,concepts,comparisons,queries}/**/*.md",
     output_mode: "content", -i: true, -C: 2, head_limit: 60)
```

### 쿼리 확장 (필수)

형태소 분석기가 없으므로 **에이전트가 직접 표기 변형을 넓힌다.** 원문 질의 한 벌만 던지고 "없음"으로 끝내지 말 것 — 한국어 볼트에서 미적중의 대부분은 부재가 아니라 표기 불일치다.

한 번의 Grep에 정규식 교대(`가상\s*스레드|virtual\s*thread|버추얼`)로 묶어 넣는다:

- **띄어쓰기 변형** — `\s*`로 흡수 (`가상 스레드` / `가상스레드`)
- **조사·어미 절단** — 어간만 남긴다 (`카프카의` → `카프카`, `설계했다` → `설계`)
- **한↔영 병기** — 한국어 용어는 영어 원어를, 영어 용어는 국문 음차를 함께 (`관측성|observability|옵저버빌리티`)
- **약어 ↔ 전개형** — `LLM|large language model`, `k8s|kubernetes`
- **하이픈·대소문자** — `-`는 `[-\s]?`로, 검색은 항상 `-i`

여러 개념이 섞인 질의는 개념별로 Grep을 나눠 돌리고 교집합 페이지를 우선한다.

## 2단계: index 폴백 (미적중일 때만)

1단계가 비었거나, 볼트가 이 주제를 어떤 어휘로 부르는지 자체가 불확실하면:

1. 루트 `index.md` **전체 Read** — 주제군 지도다. 어느 카테고리에 속하는지, 볼트가 쓰는 용어가 무엇인지 파악한다.
2. 해당 디렉토리의 `index.md`(전수 카탈로그)로 하강해 제목·요약을 훑는다.
3. 거기서 얻은 어휘로 1단계 Grep을 다시 돌린다.

index는 **폴백이자 쿼리 어휘 공급원**이지 1차 경로가 아니다. 등재율이 완전하지 않을 수 있으므로 index에 없다는 이유로 페이지가 없다고 결론내지 않는다.

## 3단계: 후보 선별 · 본문 확장

- Grep 컨텍스트로 관련성을 판단해 **상위 1~5개만** 선별한다.
- 선별한 파일을 **Read**하여 전체 본문 확인.
- 각 페이지의 `[[wikilink]]`를 따라 1-hop 이웃도 필요 시 확인.
- 적중 파일을 무턱대고 전부 Read하지 말 것 — 스니펫으로 좁힌 뒤 최소한만 확장(토큰 절약).

## 결과 제공

```
## 위키 검색 결과: $ARGUMENTS

### 발견된 페이지
1. [[페이지명]] — 핵심 요약 1~2줄
2. [[페이지명]] — 핵심 요약 1~2줄

### 종합
- 현재 작업에 적용 가능한 패턴/결정/교훈. "Based on [[page-a]] and [[page-b]]..." 식으로 출처 페이지 인용.

### 연결된 페이지
- [[관련페이지]] — 관련 이유
```

## 답변 파일링 (Query Feedback)

합성한 답변이 **재도출하기 아까운 수준**(실질적 비교 분석, 딥다이브, 신규 합성)이면 저장을 제안한다:

> "이 분석을 위키에 저장할까요? (queries/ 또는 comparisons/)"

사용자가 동의하면 wiki-schema 스킬 규칙대로:

1. SCHEMA.md frontmatter 형식으로 `queries/`(일반 합성) 또는 `comparisons/`(A vs B)에 Write — `type: query` 또는 `comparison`, `summary:` 한 줄 필수, `sources:`에 인용한 위키 페이지 표기
2. outbound `[[wikilink]]` 최소 2개 포함, 관련 페이지 최대 5개에 역링크 삽입
3. `log.md` 끝에 `## [YYYY-MM-DD] query | {주제}` append (파일링 여부 명시)
4. 정비 실행 — index 재생성과 오류 점검:
   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/scripts/lint.mjs" --vault "$WIKI"
   ```
   error 그룹은 그 자리에서 조치, backlog는 건수만 보고. 스크립트가 없는 환경이면 생략하고 "정비 미실행"을 한 줄 남긴다. `index.md`는 직접 편집하지 않는다.

단순 조회 결과는 파일링하지 않는다.

## 주의사항

- 전체 노트를 그대로 출력하지 말 것 (토큰 낭비). 핵심만 요약.
- **"없음"은 쿼리 확장과 index 폴백까지 마친 뒤에만 말한다.** 그 뒤에도 비었으면 "볼트에 관련 페이지 없음"으로 짧게 알리고, 시도한 확장 표기를 한 줄로 덧붙인다.
- 현재 작업 맥락과 연결해서 어떻게 활용할 수 있는지 제안한다.
