LLM Wiki 볼트에서 "$ARGUMENTS"와 관련된 지식을 찾아 현재 작업 컨텍스트에 주입해줘.

## 볼트 경로

```bash
WIKI="${WIKI_PATH:-$OBSIDIAN_VAULT_PATH}"
```

둘 다 미설정이면 사용자에게 안내하고 중단.

## 검색 절차 (반드시 순서대로)

### 1단계: index.md 스캔 (토큰 절약 — 항상 먼저)

`$WIKI/index.md`를 키워드로 Grep하여 관련 페이지를 식별한다. 인덱스의 한 줄 요약으로 관련성을 판단한다. 전체 노트 본문을 먼저 Read하지 말 것.

### 2단계: 본문 보조 검색 (인덱스에서 부족할 때)

인덱스 매칭이 0~1건이면 병렬로 보조 검색:

1. Grep으로 본문 키워드 매칭 (`$WIKI` 전체, `*.md`, `raw/`·`.obsidian/` 제외)
2. Grep으로 frontmatter `tags:` 매칭
3. Glob으로 키워드가 포함된 파일명 탐색

후보 1~5개를 선별한다.

### 3단계: 후보 페이지 Read

선별한 후보를 병렬로 Read. 각 페이지의 `[[wikilink]]`를 따라 1-hop 이웃 페이지도 필요 시 확인.

## 결과 제공

```
## 위키 검색 결과: $ARGUMENTS

### 발견된 페이지
1. [[페이지명]] — 핵심 요약 1~2줄
2. [[페이지명]] — 핵심 요약 1~2줄

### 종합
- 현재 작업에 적용 가능한 패턴/결정/교훈. "Based on [[page-a]] and [[page-b]]..." 식으로 출처 페이지 인용.

### 연결된 페이지
- [[관련페이지]] — 관련 이유
```

## 답변 파일링 (Query Feedback)

합성한 답변이 **재도출하기 아까운 수준**(실질적 비교 분석, 딥다이브, 신규 합성)이면 저장을 제안한다:

> "이 분석을 위키에 저장할까요? (queries/ 또는 comparisons/)"

사용자가 동의하면 wiki-schema 스킬 규칙대로:

1. SCHEMA.md frontmatter 형식으로 `queries/`(일반 합성) 또는 `comparisons/`(A vs B)에 Write — `type: query` 또는 `comparison`, `sources:`에 인용한 위키 페이지 표기
2. outbound `[[wikilink]]` 최소 2개 포함, 관련 페이지 최대 5개에 역링크 삽입
3. `index.md` 해당 섹션에 행 추가 + 헤더 갱신
4. `log.md` 끝에 `## [YYYY-MM-DD] query | {주제}` append (파일링 여부 명시)

단순 조회 결과는 파일링하지 않는다.

## 주의사항

- 전체 노트를 그대로 출력하지 말 것 (토큰 낭비). 핵심만 요약.
- 검색 결과가 없으면 "볼트에 관련 페이지 없음"으로 짧게 알리고 끝낸다.
- 현재 작업 맥락과 연결해서 어떻게 활용할 수 있는지 제안한다.
