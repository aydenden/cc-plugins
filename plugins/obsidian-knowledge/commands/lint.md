Obsidian 볼트의 위키 건강 상태를 점검해줘.

## 환경변수

볼트 경로: `OBSIDIAN_VAULT_PATH` 환경변수에서 가져온다. 설정되지 않았으면 사용자에게 안내하고 중단.

## 점검 대상

`$OBSIDIAN_VAULT_PATH` 내 모든 `.md` 파일. 단, `.obsidian/` 디렉토리는 제외.

## --fix 플래그

`$ARGUMENTS`에 `--fix`가 포함되면 각 카테고리에서 자동 수정 가능한 항목을 수정한다. 없으면 보고만 한다.

## 점검 절차

### 사전 준비: 링크 맵 구축

볼트 내 모든 노트 파일명과 `[[wikilink]]` 참조를 수집한다:

1. Glob으로 `$OBSIDIAN_VAULT_PATH/**/*.md` 전체 파일 목록 수집 (`.obsidian/` 제외)
2. Grep으로 `\[\[[^\]]+\]\]` 패턴을 전체 볼트에서 추출

이 두 결과로 "존재하는 파일 집합"과 "참조되는 링크 집합"을 구성한다.

### 카테고리 1: 고아 페이지

인바운드 `[[파일명]]` 참조가 0인 노트를 찾는다.

- `_wiki/index.md`, `_wiki/log.md`는 제외 (관리 파일)
- `--fix`: 자동수정 없음. 목록만 보고.

### 카테고리 2: 깨진 링크

`[[대상]]` 형태의 링크에서 대상 파일(`대상.md`)이 볼트 어디에도 존재하지 않는 경우.

- Glob으로 `**/{대상}.md` 패턴 확인
- `--fix`: 각 깨진 링크에 대해 스텁 노트 생성을 제안

### 카테고리 3: 태그 불일치

모든 노트의 `tags:` frontmatter를 수집하여 유사 태그 쌍을 탐지한다.

- 알려진 별칭 쌍: `js`/`javascript`, `ts`/`typescript`, `react`/`reactjs`, `py`/`python`
- 대소문자 불일치: `React` vs `react`
- `--fix`: 빈도가 높은 쪽으로 통일하는 Edit 제안

### 카테고리 4: 오래된 노트 (Stale)

`source_hash` 필드가 있는 노트 중 `source`가 URL인 경우:

1. URL을 WebFetch로 다시 가져옴
2. 본문 첫 500자로 새 해시 계산
3. 저장된 `source_hash`와 비교
4. 불일치 → stale로 플래그

`source_hash`가 없는 노트는 `date` 기준 180일 이상 경과 시 경고.

- `--fix`: stale 노트에 대해 재ingest(capture) 제안

### 카테고리 5: 누락 개념

깨진 링크 목록에서 **3회 이상 참조**된 대상을 추출한다. 여러 노트에서 언급되지만 전용 페이지가 없는 개념.

- `--fix`: 각 누락 개념에 대해 capture로 페이지 생성 제안

### 카테고리 6: Frontmatter 결함

`_wiki/` 디렉토리를 제외한 모든 `.md` 파일에서 필수 frontmatter 필드를 점검:

| 필드 | 필수 여부 |
|------|-----------|
| `type` | 필수 |
| `tags` | 필수 |
| `summary` | 필수 |
| `date` | 필수 |

- `--fix`: 누락된 필드를 빈 값으로 추가하는 Edit 제안

## 출력 형식

```
## Vault Lint Report -- YYYY-MM-DD

### 요약
| 카테고리 | 건수 |
|----------|------|
| 고아 페이지 | N |
| 깨진 링크 | N |
| 태그 불일치 | N쌍 |
| 오래된 노트 | N |
| 누락 개념 | N |
| Frontmatter 결함 | N |

### [1] 고아 페이지
| 파일 | 생성일 |
|------|--------|

### [2] 깨진 링크
| 소스 파일 | 깨진 링크 |
|-----------|-----------|

### [3] 태그 불일치
| 태그 A | 태그 B | 사용 비율 |
|--------|--------|-----------|

### [4] 오래된 노트
| 파일 | 마지막 업데이트 | 해시 상태 |
|------|-----------------|-----------|

### [5] 누락 개념 (3회+ 참조)
| 개념 | 참조 횟수 | 참조하는 노트 |
|------|-----------|---------------|

### [6] Frontmatter 결함
| 파일 | 누락 필드 |
|------|-----------|

### 권고 조치
1. ...
```

## 마무리

점검 완료 후 `$OBSIDIAN_VAULT_PATH/_wiki/log.md` 상단에 엔트리를 추가한다:

```markdown
## [YYYY-MM-DD] lint
- 고아 페이지: N개
- 깨진 링크: N개
- 태그 불일치: N쌍
- 오래된 노트: N개
- 누락 개념: N개
- Frontmatter 결함: N개
```
