# Map Run — 목표 하나를 세션 여러 개로 민다

한 세션에 안 들어가는 목표는 **세션을 갈아끼우며** 민다. 문제는 그 사슬이 끊기는 자리다 — 티켓
하나를 닫고 「다음으로 갈까요?」로 멈추거나, 인계가 늦어 포화된 세션이 규약을 잊은 채 굴러간다.

**스킬은 그 사슬을 굴릴 수 없다.** 스킬은 세션 안에서만 살아서 세션 경계를 못 넘는다(`/loop` 이
이 자리의 답이 아닌 이유와 같다). 굴리는 것은 세션 밖의 셋이다.

| 층 | 무엇 | 왜 세션을 넘나 |
|---|---|---|
| **계약** | bd epic 본문 (맵 헌장) | DB 에 있다. 세션이 죽어도 남는다 |
| **강제** | `long-run` 플러그인의 Stop hook | 플러그인에 달려 있어 어느 repo·worktree 에서 연 세션에도 붙는다 |
| **운반** | `long-run:session-handoff` | 인계 문서 하나로 소유권을 넘긴다 |

이 스킬이 하는 일은 그 셋을 **세우고 거두는 것**이다. 미는 것은 그다음부터 규약과 훅이 한다.

## 언제

- 목표가 티켓 하나로 안 끝나고, 몇 세션 걸릴 것 같다
- 이미 맵이 있고 새 세션이 그것을 이어받았다 (→ 3단계부터)
- 선행 `/wayfinder` 맵이 「길이 보임」으로 닫혔고, 이제 그 길을 걸어야 한다 (→ 1단계의 물려받기)

반대로 **티켓 하나를 처리하는 것은 맵이 아니다.** 다만 티켓 한 건이 여러 세션으로 번지면 그것을
맵으로 감쌀 수 있다.

### 무엇을 할지 아직 모르면 이 스킬이 아니다

이 맵은 **실행**의 맵이다 — 완료조건에 적힌 산출물까지 민다. 무엇을 만들지가 아직 결정에 걸려 있으면
먼저 `/wayfinder` 로 그 결정들을 푼다. 판정은 하나다: **완료 조건을 관측 가능한 문장으로 지금 쓸 수
있는가.** 못 쓰면 남은 것은 작업이 아니라 결정이다.

🚨 **두 맵을 한 맵으로 합치지 않는다.** `/wayfinder` 는 「세션당 티켓 하나」, 「차팅이 끝나면 정지」가
규약이고 이 스킬의 Stop hook 은 바로 그 정지를 되민다. 같은 맵에 둘을 걸면 하네스가 wayfinder 의
규약을 위반한다. 라벨도 갈라 둔다(`long-run:map` ↔ `wayfinder:map`) — 섞이면 `/wayfinder` 의
「Work through the map」이 이 실행 맵을 집어 1티켓 규약으로 굴린다.

## 전제

`bd`(beads) 와 `orca` 가 PATH 에 있어야 한다. 없으면 그 사실을 보고하고 멈춘다 — 폴백은 없다.

## 절차

### 1. 헌장을 쓴다 (티켓보다 먼저)

`${CLAUDE_PLUGIN_ROOT}/skills/map-run/assets/map-charter.md` 를 채운다. 템플릿을 읽지 않고 쓰지
않는다 — 「운영 규약」 절의 고정 문구가 이 스킬의 실체이고, 그 문장이 다음 세션의 유일한 지침이 된다.

**Destination 과 완료 조건은 사용자와 합의한다.** 여기가 어긋난 채 세운 맵은 몇 세션을 밀고 나서야
어긋난 것이 드러난다. 나머지 절은 지금 아는 만큼만 채우고, 맵이 굴러가며 `bd update --append-notes`
로 자란다(`--notes` 는 덮어쓴다).

**선행 `/wayfinder` 맵이 있으면 거기서 물려받는다** — 다시 합의하지 않는다. 절 대응은 그대로다:

| wayfinder 맵 | 헌장 |
|---|---|
| Destination | Destination (그대로. 어긋나면 어느 쪽이 맞는지 사용자에게 묻는다) |
| Decisions so far | 확정된 결정 — 링크만 두지 말고 한 줄 요지까지 옮긴다 |
| Not yet specified | 아직 규정 못 한 것 + 지금 말할 수 있는 것은 2단계의 초기 티켓으로 |
| Out of scope | 범위 밖 |
| Notes | 운영 규약에 덧붙일 것이 있는지만 본다 |

```bash
bd create -t epic -p 1 --labels long-run:map -t "{한 줄 목적지}" --description-file {헌장경로}
```

### 2. 프론티어를 깐다

자식 티켓을 만든다. **첫 티켓은 측정이다** — 크기를 모르는 채 구현 티켓을 쪼개면 그 분할이 틀린 채
맵 전체에 퍼진다. 측정 티켓이 낸 크기·경계로 후속 티켓을 만드는 것이 그 티켓의 완료 조건이다.
선행 wayfinder 맵이 이미 그 크기를 재 놓았으면 측정 티켓을 또 만들지 않는다.

```bash
bd create -t task -p 1 --parent {맵id} -t "{측정할 것}"
```

**티켓으로 만들 것과 안개에 둘 것을 가른다.** 기준은 「지금 답할 수 있나」가 아니라 **「지금 질문을
정확히 말할 수 있나」** 다 — 말할 수 있으면 막혀 있어도 티켓이고, 못 하면 헌장의 「아직 규정 못 한 것」에
적는다. 안개를 미리 티켓 크기로 썰지 않는다. 한 덩이가 나중에 티켓 셋이 될 수도, 하나도 안 될 수도 있다.

자식이 하나도 없으면 3단계에서 가드가 곧바로 「프론티어 비었음」으로 판정하고 선언을 지운다.

### 3. 이 세션이 맵을 민다고 선언한다

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/frontier-guard.mjs" claim {맵id}
```

이 한 줄이 없으면 훅이 붙어 있어도 아무것도 안 한다 — 가드는 선언한 맵에만 붙는다. 선언 뒤
`status` 로 판정이 서는지 본다(마커·열린 자식이 보여야 한다):

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/frontier-guard.mjs" status
```

마커는 **지금 위치의 worktree 별로** 갈린다(`$HOME/.claude/long-run/frontier-guard/<키>.json`,
`LONG_RUN_STATE_ROOT` 로 옮긴다). 그래서 병렬 worktree 의 세션들은 서로를 건드리지 않고, 같은
worktree 에 뜬 인계 세션은 같은 선언을 물려받는다.

### 4. 민다

`bd ready` → `bd update {id} --claim` → 작업 → `bd close {id} --reason "{관측}"` → **곧장 다음 티켓.**
사이에서 사용자에게 묻지 않는다. 멈춰도 되는 자리 넷은 헌장에 있다.

**묻는 것은 갈림길뿐이다.** 목적지·완료 조건을 고쳐 쓰게 되거나 되돌리기 비싼 것을 확정하는 선택(A/B)만
한 줄로 묻고, 답을 헌장의 「확정된 결정」에 근거까지 적는다. 어느 쪽을 골라도 완료 조건의 참/거짓이 같은
국소 선택(A.1/A.2)은 **묻지 않고 고르고 이유를 `--reason` 에 남긴다** — 다음 세션이 다시 고르게 만드는
것이 이 자리의 실패다. 판정이 서지 않는 것 자체가 갈림길이라는 신호다(완료 조건으로 못 가른다는 뜻).
기준은 헌장이 소유한다.

작업 중 새 미지수가 나오면 현재 티켓을 넓히지 말고 형제를 만든다:

```bash
bd create -t task --parent {맵id} --deps discovered-from:{현재id} -t "{발견}"
```

티켓을 닫을 때 **그 답이 안개를 걷었는지** 본다. 「아직 규정 못 한 것」의 한 덩이를 이제 정확히 말할 수
있으면 그 자리에서 티켓으로 만들고 **헌장에서 그 줄을 지운다.** 반대로 목적지 밖이었다고 드러나면
티켓을 닫고 「범위 밖」에 한 줄 남긴다 — 길 위의 한 걸음이 아니므로 「확정된 결정」에는 넣지 않는다.

### 5. 경계에서 넘긴다

컨텍스트 50% 를 넘기면 가드가 멈춤을 한 번 되밀며 인계를 지시한다. 그때
`long-run:session-handoff` 를 부르고, `--bd {맵id}` 를 붙인다. **헌장의 운영 규약이 인계 문서 §0 으로
들어가야 한다** — §0 의 나머지 규칙은 그 템플릿이 소유한다.

🚨 **인계하며 `clear` 하지 않는다.** 마커는 worktree 당 파일 하나라, 지우면 새 세션이 가드 없이
출발한다. 보내는 세션은 지우지 않아도 멈출 수 있다 — 가드는 멈춤 시도마다 한 번만 되밀고 두 번째는
무조건 통과시킨다. 대가로 **같은 worktree 에서 세션 둘을 동시에 굴리면** 다른 세션도 이 맵으로
판정된다.

### 6. 끝난다

프론티어가 비면 가드가 스스로 마커를 지우고 그 세션은 멈출 수 있게 된다. 맵을 닫는다:

```bash
bd close {맵id} --reason "{도착지에 닿았다는 관측. 다음 맵의 출발점이 될 표·경로를 여기 남긴다}"
```

닫기 전에 두 절을 읽는다. 헌장의 **완료 조건 각 줄을 참/거짓으로** 읽고, **「아직 규정 못 한 것」이
비었는지** 본다. 거짓인 줄이 있거나 안개가 남았는데 프론티어가 비었다면 티켓을 안 만든 것이지 끝난 것이
아니다.

## 함정

- **프론티어가 비는 자리를 의심한다.** 측정 티켓이 후속을 안 낳았거나, 안개 한 덩이를 티켓으로
  졸업시키지 않았거나, 내가 만든 티켓을 내 판단으로 보류했거나 — 셋 다 「다 했다」로 잘못 읽힌다.
  가드는 열린 자식의 **수만** 보지 이유를 못 본다. 헌장의 「아직 규정 못 한 것」이 사람이 그 차이를
  볼 수 있는 유일한 자리다
- **bd 가 잠깐 죽으면 선언이 사라진다.** 가드는 `bd list` 실패를 빈 프론티어와 구분하지 못하고 마커를
  지운다(`scripts/frontier-guard.mjs` 의 `openChildrenOf`). 세션이 갑자기 안 막히면 먼저 `status` 를
  보고, 마커가 없으면 3단계를 다시 한다
- **cwd 가 git 저장소 밖이면 키가 cwd 로 떨어진다.** 그 상태로 폴더를 옮겨 다니면 선언을 못 찾아
  가드가 **아무것도 안 하는 쪽**으로 고장난다(막는 쪽이 아니다). `status` 의 `markerPath` 로 확인한다
- **훅은 세션이 뜰 때 읽힌다.** `hooks/hooks.json` 을 고쳤으면 새 세션부터 적용된다
- **가드는 못 멈추게 하는 장치가 아니다.** 멈춤 시도마다 한 번 되밀 뿐이다. 그 선을 넘는 설계는
  만들지 않는다 — 넘기면 사용자가 Ctrl+C 로만 빠져나오게 된다
- **맵 본문은 절차서가 아니다.** 어느 스킬을 부를지만 적고 절차는 스킬에 남긴다. 요약해 옮기면 새
  세션이 스킬을 안 부르고 요약만 따라간다

## Improvement rule

맵을 밀며 발견한 마찰은 소유한 곳에 그 자리에서 반영한다 — 헌장 형식은 `assets/map-charter.md`,
판정 축과 되미는 문구는 `scripts/lib/guard-core.mjs`, 인계 문서 형식은 `long-run:session-handoff` 의
`references/handoff-doc.md`. 절차 자체가 바뀌면 사용자와 합의한 뒤 이 SKILL.md 를 고친다.
